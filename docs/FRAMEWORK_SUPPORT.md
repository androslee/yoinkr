Reviewed **2026-10-24**, against Yoinkr **v0.30.0**. This page records delivered evidence separately from future investigation candidates. It is documentation, not automatic framework detection or a new integration capability.

## Additional frameworks and current work

**Not started** means no delivered application-specific GUI extraction/integration and acceptance proof in this project. Researching the examples below does not change that status. These are distinct investigation families even when they share a language or rendering engine.

| Framework / architecture family | Status | Work needed for a first credible proof |
| --- | --- | --- |
| Qt Quick/QML and Qt language bindings | Not started | Qt Widgets/Krita→OBS does not establish QML, PyQt or PySide host integration; each needs its own source/runtime and GUI acceptance. |
| GTK / gtkmm / libadwaita | **In progress — not verified** | Pinned GIMP smoothing C source recovered; numeric/source-slice comparison passes. No GTK controls have run. Original GIMP/GTK donor observation remains required; no GTK widget/recipient integration is claimed. [Gate and setup](CREATOR_EXAMPLES.md). |
| wxWidgets | Not started | Identify the feature's event/resource dependencies and platform port; build one recipient adapter. |
| .NET WPF | Not started | Recover managed behavior and XAML/resources; bind UI thread/lifecycle and verify a real WPF host. |
| .NET Windows Forms | Not started | Recover forms, controls and dependencies; verify host events, resources, disposal and rollback. WPF proof would not imply WinForms proof. |
| Avalonia | Not started | Recover managed behavior and Avalonia resources; verify a real recipient and target backend. |
| Flutter desktop | Not started | Establish Dart/source or compiled recovery route plus native plugins/assets; verify desktop recipient behavior. |
| Tauri | Not started | Bind the web frontend, Rust commands, permissions and system webview for the selected platform. Electron patches cannot be assumed to work. |
| Java Swing / AWT | Not started | Recover a bounded JVM feature and resources; bind the event-dispatch thread, services and lifecycle. |
| Eclipse SWT / RCP | Not started | Establish SWT native dependencies and, for RCP, OSGi/workbench services; verify a real recipient. |
| JavaFX | Not started | Recover Java modules, FXML/CSS/resources and controller services; verify scene/thread ownership. |
| Apple AppKit / Cocoa | Not started | Investigate a specific macOS UI feature, native dependencies and recipient integration; add macOS acceptance. |
| Native Windows Win32 family, including MFC/WTL | Not started | Investigate actual window/message/resource ownership and ABI dependencies; add Windows acceptance. MFC and WTL are not interchangeable APIs. |
| Gecko / Firefox application family | Not started | Develop a dedicated browser/application integration route and verify the selected app. Electron/Chromium evidence does not apply. |

## Additional families still awaiting investigation

The catalog is curated, not exhaustive. **CEF and WebView2 embedding, WinUI 3 / Windows App SDK, SwiftUI-first apps, .NET MAUI / Uno, NW.js, Compose Multiplatform, JUCE, FLTK, Fyne and Iced are also not started.** No five-app list has been validated for these families yet. A webview or native library inside an app does not, by itself, identify the app's main UI framework.

## Keeping the status honest

Before promoting a family from “not started,” retain the exact donor/recipient versions, platform, recovered feature/dependency boundary, integration route, original-vs-recipient checks, failure/lifecycle behavior and rollback evidence. A scanner result, successful launch or upstream provider capability alone is insufficient. Record partial routes as partial rather than promoting the whole framework.

Update the status tables and [examples guide](FRAMEWORK_EXAMPLES.md) when new proof lands. Keep historical release verification files unchanged; this page summarizes those releases and should link to new evidence as it becomes available.
